PROJECT OVERVIEW
================================================================================
This is a FastAPI-based IP geolocation service that provides comprehensive 
information about IP addresses including geographic location, network details,
currency, and dial codes.

DATABASE SCHEMA
================================================================================

Database File: ripe.sqlite
Type: SQLite3

TABLES:
--------

1. ip_ranges
   Purpose: Stores IP address ranges with ASN and network information
   Schema:
   - start_ip (INTEGER): Start of IP range (as integer)
   - end_ip (INTEGER): End of IP range (as integer)
   - country (TEXT): 2-letter country code (e.g., "US", "GB")
   - netname (TEXT): Network name
   - org (TEXT): Organization name
   - source (TEXT): Data source identifier
   
   Query Method: Range-based lookup
   WHERE start_ip <= queried_ip AND end_ip >= queried_ip
   
   Example Record:
   start_ip: 1442840576 (86.62.0.0)
   end_ip: 1442906111 (86.62.255.255)
   country: "TR"
   netname: "TURKTELEKOM"
   org: "Turk Telekom"

2. City_layer
   Purpose: Stores IP ranges with detailed geolocation data
   Schema:
   - start_ip (TEXT): Start of IP range (32-char zero-padded hex)
   - end_ip (TEXT): End of IP range (32-char zero-padded hex)
   - country_iso_code (TEXT): 2-letter country code
   - city_name (TEXT): City name
   - subdivision_1_name (TEXT): State/Province/Region
   - postal_code (TEXT): Postal/ZIP code
   - time_zone (TEXT): IANA timezone (e.g., "America/New_York")
   - latitude (REAL): Latitude coordinate
   - longitude (REAL): Longitude coordinate
   
   Query Method: Range-based lookup (same as ip_ranges)
   
   Example Record:
   start_ip: 1442840576
   end_ip: 1442906111
   country_iso_code: "TR"
   city_name: "Istanbul"
   latitude: 41.0082
   longitude: 28.9784

3. country_currency
   Purpose: Maps country codes to currency information
   Schema:
   - country_code (TEXT PRIMARY KEY): 2-letter ISO country code
   - currency_name (TEXT): Full currency name (e.g., "US Dollar")
   - currency_code (TEXT): 3-letter currency code (e.g., "USD")
   
   Data Source: pycountry library
   
   Query Method: Direct lookup by country code
   
   Example Record:
   country_code: "US"
   currency_name: "US Dollar"
   currency_code: "USD"

4. country_dial
   Purpose: Maps country codes to international dial codes
   Schema:
   - country_code (TEXT PRIMARY KEY): 3-letter ISO-3 country code
   - dial_code (TEXT): International dialing code (e.g., "1", "44")
   
   Data Source: country_dial.csv
   
   Query Method: Direct lookup by ISO-3 country code
   
   Example Record:
   country_code: "USA"
   dial_code: "1"

5. fallback_city
   Purpose: Provides capital city as fallback when city data is unavailable
   Schema:
   - country_code (TEXT PRIMARY KEY): 3-letter ISO-3 country code
   - capital_city (TEXT): Capital city name
   
   Data Source: country_dial.csv (Capital column)
   
   Query Method: Direct lookup by ISO-3 country code
   Used when: city is NULL or "N/A"
   
   Example Record:
   country_code: "USA"
   capital_city: "Washington"

DATA FLOW
================================================================================

1. IP Query Received (IPv4 or IPv6)
   ↓
2. Convert IP String to 32-Character Hex
   Example (IPv4): "8.8.8.8" → "00000000000000000000000008080808"
   Example (IPv6): "2001:db8::" → "20010db8000000000000000000000000"
   ↓
3. Query City_layer Table (PRIMARY)
   Find range where start_ip <= hex_ip <= end_ip (Hex comparison)
   Returns: country, city, region, postal, timezone, lat, lon
   ↓
4. Query ip_ranges Table (SECONDARY - If IPv4)
   Find range using integer comparison (Legacy / Network info)
   Returns: netname, org, source (supplementary network info)
   ↓
5. Enrich with Country Data
   a) Get country_alpha3 using pycountry
   b) Query country_currency for currency info
   c) Query country_dial for dial code
   ↓
6. Apply City Fallback (if needed)
   If city is NULL or "N/A":
      Query fallback_city for capital city
   ↓
7. Return Complete JSON Response

IP RANGE LOOKUP ALGORITHM
================================================================================

The system uses range-based lookups, not exact IP matching.

Why Range-Based?
- IP addresses are allocated in blocks (CIDR notation)
- All IPs in a block share the same metadata
- More efficient than storing individual IPs

Query Logic:
SELECT * FROM [City_layer] 
WHERE start_ip <= ? AND end_ip >= ? 
ORDER BY (end_ip - start_ip) ASC 
LIMIT 1

Mechanism:
1. Every IP (v4 or v6) is normalized to a 32-character hex string.
2. Standard SQLite string comparison handles the range lookup.
3. This eliminates the 64-bit integer limitation for IPv6.

Key Points:
1. City_layer is queried first as it provides better coverage.
2. finds all ranges containing the IP
3. Orders by range size (smallest first)
4. Returns most specific match
5. ip_ranges is used to supplement network metadata (org/netname).

Example:
Query: 86.62.2.251
Matches: 86.62.0.0/16 (large ISP block)
Also Matches: 86.62.2.0/24 (specific subnet)
Returns: 86.62.2.0/24 (more specific)

DATA ENRICHMENT PIPELINE
================================================================================

Stage 1: Base IP Lookup
- Query ip_ranges and City_layer tables
- Get basic network and location data

Stage 2: Country Code Normalization
- Convert 2-letter code to ISO-3 using pycountry
- Get full country name and numeric code

Stage 3: Currency Enrichment
- Lookup currency using 2-letter country code
- Add currency_name and currency_code

Stage 4: Dial Code Enrichment
- Lookup dial code using ISO-3 country code
- Add dial_code with "+" prefix

Stage 5: City Fallback
- Check if city is NULL or "N/A"
- If yes, lookup capital city using ISO-3 code
- Replace city with capital

Stage 6: Response Assembly
- Combine all data into single JSON object
- Return to client

TROUBLESHOOTING
================================================================================

Issue: IP not found
Solution: Check if IP range exists in database

Issue: Missing city data
Solution: Verify City_layer table has data for that range
          Fallback should provide capital city

Issue: Missing currency/dial code
Solution: Run import scripts to populate lookup tables

Issue: Slow performance
Solution: Add indexes on start_ip and end_ip columns
          Consider migrating to PostgreSQL
